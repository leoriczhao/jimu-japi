# 2026-11-18 SDK 基线

目标：把接口诊断、回调清理、打包诊断、代码化物编和基础 UI 固定为可以从明确提交重建、验证的 SDK，再用该 SDK 开发独立单人地图。

当前为基线候选，正在完成干净构建与产物验证。完成前不把本页视为发布通过记录。

## 输入与范围

- Windows、Warcraft III 1.27a；内嵌 Lua 5.4、Win32 Release。
- Visual Studio 2022 C++ 工具链和 CMake；实际版本、编译命令、源码提交与二进制 SHA-256 记入产物 manifest。
- w3x2lni 脚本/数据固定到 `tools/fetch-w3x2lni.ps1` 的默认提交，vendor 的实际文件使用 SHA-256 清单固定。
- SDK 原生 D3D API 版本保持 `0.4.0`；基线由独立提交/tag 识别，避免把工具层更新混同于 ABI 版本变化。
- 包含单位/技能的明确物编字段子集、按钮和固定尺寸行列布局；不声称通用多人同步或通用脚本热更新已完成。

## 验证要求

1. 从固定提交创建干净 detached worktree，使用其源码和模板完整构建，禁用 `-NoBuild`。
2. 两次独立干净构建比较三个可执行产物的 SHA-256；记录相同工具链与实际依赖，不把未验证的跨编译器结果称作位级复现。
3. SDK 作者包的全部校验和逐项回读；在包内运行示例静态/打包、物编与 UI 实机测试。
4. 使用同一份基线 DLL 运行原生 ABI、接口一致性和普通游戏回归；结果行必须存在且零失败，跳过项单独记录。
5. 冻结基线提交/tag，后续地图工程引用该基线版本与产物哈希。

## 当前已知边界

本地命令测试存在偶发失败记录，见 [STATUS](STATUS.md)。D3D UI 需要游戏目录 proxy。本机实机覆盖不等于其他补丁、其他显卡或多人一致性保证。

验证结果与确切产物路径将在构建完成后补入本页。
